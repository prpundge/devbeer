# Specification — 2.2.0

**Released as:** DevBeer · **Commit:** `972facf` · **Status:** uploaded, in Marketplace review

Two new modules — **JSON Formatter** and **Folder Compare** — and a rewrite of the JSON
handling that both build on.

---

## 1. Scope

### Goals

1. A real JSON formatter, not a whitespace shuffler.
2. A "Beyond Compare"-style comparison feature.
3. Version bump.

### Design decision: what "Beyond Compare-style" should mean here

Beyond Compare's signature capability is **folder** comparison. IntelliJ already ships a
directory diff, so cloning it would add maintenance burden and no user value.

The gap worth filling is that the IDE's diff is **format-blind**: it can tell you two
`application.yml` files differ, but not *how*, and it cannot compare a `.properties` file
against a YAML file at all — a text diff of those is noise.

So Folder Compare is **config-aware**: it reports key-level deltas inline and routes config
pairs to the existing Property Compare. That is the delta over the built-in, and it reuses
the `props` foundation from 2.0.0 rather than duplicating it. (Constitution §IV.)

## 3. Module: JSON

### Why a parser replaced the formatter

The 2.0.0 pretty-printer walked the character stream moving whitespace. Three consequences,
all of which are silent-wrong-answer failures:

1. It could not say **why** a document was malformed — only produce malformed output.
2. It **rewrote values**. Any float-based round trip turns `1.0` into `1`, `1e3` into `1000.0`
   and `0.1000` into `0.1`.
3. It **collapsed duplicate keys**, which the JSON grammar permits.

### FR-JSON-1 — Recursive-descent parser

`JsonParser`, producing a `JsonValue` tree.

| Design choice | Reason |
|---|---|
| `JsonNumber` holds the **raw text** | `1.0`, `1e3`, `0.1000`, `-0`, `2.5E-8` round-trip exactly |
| `JsonObject` holds an **ordered list**, not a map | Preserves order *and* duplicate keys |
| Depth limit 512 | A 2000-deep document reports "Nesting is deeper than 512 levels" instead of overflowing the stack |

### FR-JSON-2 — Positional diagnostics

`JsonSyntaxException` carries `reason`, `line`, `column`, `offset`. The panel puts the caret
on the offending character.

### FR-JSON-3 — Lenient mode

Accepts what people actually write in config files: `//` and `/* */` comments, trailing
commas, single-quoted strings. Output is always strict JSON.

### FR-JSON-4 — Formatting

| Operation | Detail |
|---|---|
| Pretty | Indent 2 spaces / 4 spaces / tab |
| Minify | No insignificant whitespace |
| Sort keys | Recursively, every level |
| Empty containers | `{}` and `[]` stay on one line |
| Escaping | `"` `\` `\n` `\r` `\t` `\b` `\f`, other control chars as `\uXXXX` |

### FR-JSON-5 — Tool window

Input/output split, live validation, indent selector, sort-keys and lenient toggles, copy,
chain output→input, load from / write back to editor.

### FR-JSON-6 — `Format JSON` editor action

Reformats the selection, or the whole file, as one undoable command. Lenient on input, strict
on output. A syntax error produces a notification with the position and **leaves the document
untouched**.

### FR-JSON-7 — String Toolbox transforms

`json-pretty` and `json-minify` re-backed by the parser, plus `json-pretty-lenient`,
`json-sort-keys`, `json-validate`. Total transforms: 71 → **74**.

## 4. Module: Folder Compare

### FR-FOLD-1 — Tree comparison

Both trees walked, merged on relative path. Status per file: `SAME`, `DIFFERENT`,
`ONLY_LEFT`, `ONLY_RIGHT`.

### FR-FOLD-2 — Content comparison

Length first (free, and unequal length can never be equal content), then SHA-256 over a 64 KB
streaming buffer. `compareContents = false` treats equal-size files as identical for a fast
pass. Files above 20 MB fall back to size comparison.

### FR-FOLD-3 — Key-level delta *(the differentiator)*

For `.properties`/YAML pairs that differ, a **Key differences** column computed via the
existing `PropertyDiffEngine`: `"2 changed, 1 only left"`.

### FR-FOLD-4 — Type-aware navigation

| Double-click | Opens |
|---|---|
| Config pair | Property Compare, keys loaded |
| Any other pair | IDE side-by-side diff |
| One-sided entry | The file itself |

Config pairs are routed away from the text diff on purpose: a text diff of YAML against
`.properties` conveys nothing.

### FR-FOLD-5 — Skip list

`.git .hg .svn .idea .gradle build out target node_modules __pycache__ .venv venv dist .next`
— toggleable.

### FR-FOLD-6 — Background execution

Runs as a cancellable `Task.Backgroundable` with per-file progress.

### FR-FOLD-7 — Bounded work

Capped at 50,000 files. When truncated the summary says so — a silent cap would read as
"everything compared".

mode, top-level scalars, 400-deep nesting succeeding and 2000-deep reporting a limit.

### Known gaps — stated, not hidden

- **`FolderDiffEngine.compare` is not integration-tested.** It needs the IntelliJ VFS, so only
  its pure parts — `KeyDelta.describe()` and the report layout — have unit tests. The tree
  walk, SHA-256 comparison and skip list have static verification only and would need
  `./gradlew runIde` to confirm end to end.
- UI panels remain untested, as in every prior version.
