# Specification — 2.1.0

**Released as:** DevBeer · **Commit:** `64e4f41` · **Status:** live on the Marketplace

A rebrand and a compatibility widening. No new features — but the widening exposed a latent
crash, which makes this the release where the verification process paid for itself.

---

## 1. Scope

### Goals

1. Rename to **DevBeer** with a new logo.
2. Lower the minimum supported IDE as far as is *actually* safe.

### Non-goals

New functionality. Deliberately none, so the compatibility change could be evaluated alone.

## 4. The compatibility change

### The request, and why it could not be met as asked

The ask was "2020 and above". That is not reachable, and the reason is structural rather than
a matter of effort:

| Blocker | Introduced |
|---|---|
| `codeInsight.declarativeInlayProvider` — the whole Spring hints module | **2023.3** |
| `ContentFactory.getInstance()` | 2022.3 |
| `ActionUpdateThread` | 2022.2 |
| `Service.Level` | 2021.3 |
| IntelliJ Platform Gradle Plugin 2.x minimum target | 2022.3 |

`sinceBuild` is not a dial that adds support. Setting it to 201 would make the plugin
*installable* on IDEs where it then fails to load with `NoClassDefFoundError` — worse than
not offering it, and the Marketplace verifier would reject it.

### What each older target would actually cost

| Target | Work required |
|---|---|
| **2023.3** | None — chosen |
| 2022.3 | Rewrite the inlay hints against the pre-declarative API; replace `ContentFactory.getInstance()` and `Service.Level` |
| 2021.x | The above plus `ActionUpdateThread` shims |
| 2020.x | All the above **and** abandon the IntelliJ Platform Gradle Plugin 2.x for the legacy 1.x plugin |

**Decision: floor at 233**, keeping every feature. This roughly triples the addressable IDE
range at zero risk. The reason is recorded in `gradle.properties` beside the number so it is
not "corrected" later by someone who reads it as a preference.

## 5. Defect found by lowering the floor

### DEF-2.1-1 — `NoSuchMethodError` on 2023.3 *(severity: critical, caught pre-release)*

`SpringPropertyIndex.getInstance` used Kotlin's reified `project.service<T>()`. That helper
**inlines** a call to `com.intellij.openapi.components.ServicesKt.serviceNotFoundError`, which
does not exist before 2024.1.

Consequence had it shipped: every inlay hint on a 2023.3 IDE would have thrown.

```
Invocation of unresolved method
  ServicesKt.serviceNotFoundError(ComponentManager, Class)
  -> can lead to NoSuchMethodError at runtime
```

**Fix:** `project.getService(SpringPropertyIndex::class.java)` — the stable Java API, present
on every supported build.

**How it was caught:** `verifyPlugin` configured to check the *declared floor explicitly*
rather than trusting `recommended()`. Nothing in the source reads as wrong; only the
bytecode-level check finds it. This is now Constitution §II.

**Follow-up:** the remaining 13 version-sensitive platform calls were audited; all predate
2023.3.
