# Specification — 1.0.0

**Released as:** Spring Boot Property Viewer · **Commit:** `12adb7f` · **Status:** superseded by 2.0.0

A single-feature plugin: show the resolved value of a Spring Boot property next to the
`@Value` annotation that reads it.

---

## 1. Scope

### Goal

Remove the context switch of "which value does this property actually have in prod?" — open
`application-prod.yml`, find the key, come back — by putting the answer in the editor.

### Non-goals

- Editing configuration
- Any file comparison
- Any IDE other than a Java-capable one

## 3. Features

### FR-HINT-1 — `@Value` inlay hint

An inlay hint after a `@Value` annotation showing the resolved value per profile.

- Trigger: `PsiAnnotation` whose qualified name is
  `org.springframework.beans.factory.annotation.Value`
- Key extraction: the annotation's `value` attribute, stripped of quotes; if it matches
  `${…}`, the text before the first `:` is the key
- Presentation: `[profile: value]` pairs joined by spaces, prefixed with `→`
- Rendered with `hasBackground = true` at the annotation's end offset

### FR-HINT-2 — Profile resolution

Profiles are derived from the file name: any project file matching
`application*.{yml,yaml,properties}`. A `-` in the base name means everything after it is the
profile; otherwise the profile is `default`.

### FR-HINT-3 — Value lookup

`.properties` files are read with `java.util.Properties`. YAML is read by a hand-written
reader that walks the dotted key path.

| `META-INF/plugin.xml` | Descriptor |
| `messages/SpringPropsBundle.properties` | One key: `provider.name` |

Two Kotlin files, ~150 lines total.

### Extension point

```xml
<codeInsight.declarativeInlayProvider
    language="JAVA"
    isEnabledByDefault="true"
    implementationClass="com.plugin.springprops.SpringValueInlayProvider"
    providerId="spring.boot.property.hints"
    group="TYPES_GROUP"/>
```

`TYPES_GROUP` was wrong — these are values, not types. Corrected to `VALUES_GROUP` in 2.0.0.

## 6. Known defects

All were found and fixed during 2.0.0. They are recorded here because they define what that
release actually had to repair.

### DEF-1 — The YAML reader lost most keys *(severity: high)*

`parseYaml` tracked one `partIndex` into the dotted key path and reset it to 0 on **any**
dedent, regardless of depth. In a file with more than one nested block, every key after the
first block was silently missed.

```yaml
spring:
  datasource:
    url: jdbc:...      # found
server:
  port: 8080           # NOT found — state was reset
```

The failure was silent: no error, just "unresolved" or a missing hint. Fixed in 2.0.0 by a
real indentation-stack parser.

### DEF-2 — `@ConfigurationProperties` was never implemented *(severity: medium)*

The store description read "inlay hints for `@Value` **and `@ConfigurationProperties`**". Only
`@Value` was handled; there is no reference to the annotation anywhere in the source.
Implemented in 2.0.0.

### DEF-3 — Full rescan per hint *(severity: high, performance)*

`resolveProperty` called `FilenameIndex.getAllFilenames(project)`, filtered it, and re-read and
re-parsed every matching file — **on every annotation, on every inlay pass**. No caching.
Fixed in 2.0.0 with a project-level service cached against the VFS modification count.

### DEF-4 — Unused required dependency *(severity: low)*

`com.intellij.properties` was required but unused, narrowing installability for nothing.

## 7. Compatibility contract

Declared `241`–`242.*`. Correct for the APIs used: the declarative inlay-hints API is a 2023.3
API, so the true floor was lower than declared — but nothing was lost, since the *required*
Java dependency restricted the audience far more than the build range did.
