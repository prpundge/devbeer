# Specification — 2.0.0

**Released as:** Dev Utility · **Commit:** `17b4539` · **Status:** live on the Marketplace

The release that turned a single-feature plugin into a multi-tool, and repaired the three
defects 1.0.0 shipped with.

---

## 1. Scope

### Goals

1. Add a **Property & YAML file comparison** module with an interactive UI.
2. Add a **String Toolbox** of everyday text transformations.
3. Fix the 1.0.0 defects: the YAML reader, the unimplemented `@ConfigurationProperties`, and
   the per-hint full rescan.
4. Stop requiring Java, so the new modules work in every JetBrains IDE.

### Explicitly kept

The plugin id. A rename creates a second listing and orphans the first, so the id stayed and
this shipped as an in-place update — the 3 existing downloads carried over.

## 3. Architecture

```
com.devutility
├── DevUtilityBundle          message bundle
├── props/                    shared config parsing — no UI, no IntelliJ UI deps
│   ├── PropertyModel         PropertyEntry, PropertyFormat, PropertySnapshot
│   ├── PropertiesParser      .properties reader, keeps line numbers
│   ├── YamlParser            indentation-stack YAML reader + renderer
│   ├── PropertyFiles         VFS reading, project scanning, profile naming
│   └── PropertyDiff          diff engine, normalisation, report
├── compare/                  Property Compare tool window + actions
├── strings/                  String Toolbox tool window + actions
└── springprops/              Spring inlay hints (Java only)
```

`props` is deliberately UI-free and platform-light: it is the shared foundation the compare
module, the Spring hints and (later) the folder module all sit on.

## 4. Module: Property & YAML Compare

### FR-CMP-1 — Cross-format comparison

Both sides are flattened into the same dotted key space before comparison, so
`.properties` ↔ `.properties`, YAML ↔ YAML and **`.properties` ↔ YAML** all work.

### FR-CMP-2 — Interactive table

Columns: Key, left value, right value, Status. Status is one of `SAME`, `DIFFERENT`,
`ONLY_LEFT`, `ONLY_RIGHT`, each with its own row colour in both themes.

### FR-CMP-3 — Filtering

Free-text search over key and both values; *Only differences* toggle. Counts in the status
bar always reflect the full comparison, with "(showing n)" appended when filtered.

### FR-CMP-4 — Navigate to source

Double-click a value cell opens that file at that key's line. Double-clicking the key column
goes to whichever side has the key. This is why both parsers record line numbers —
`java.util.Properties` cannot, which is why it is not used.

### FR-CMP-5 — Two side-by-side views

- **Normalized** — both files rendered as sorted `key = value` and opened in the IDE diff
  viewer. This is what makes a YAML file and a `.properties` file line up row for row.
- **Raw** — the literal file contents in the same viewer, editable.

### FR-CMP-6 — Comparison options

`ignoreCase` and `trimValues` (default on).

### FR-CMP-7 — Reports

Grouped plain-text report, to clipboard or opened as a scratch file.

### FR-CMP-8 — Unsaved content

Reads the in-memory `Document` when one exists, falling back to disk — so a file being edited
compares as it appears on screen.

| Hash | 5 |
| JSON / XML | 6 |
| Lines | 16 |
| Text | 9 |
| Config files | 4 |

### FR-STR-2 — Live preview

Recomputed on input change, skipped above 200,000 characters.

### FR-STR-3 — Case transforms apply per line

So a pasted list of identifiers converts in one pass. Word splitting handles separators *and*
camel humps, keeping acronyms intact: `HTTPServerName` → `http-server-name`.

### FR-STR-4 — Editor integration

`Transform Selection…` (searchable popup, one undoable command) and `Send Selection to
String Toolbox`.

### FR-STR-5 — Report transforms excluded from the editor action

`editorSafe = false` hides statistics, word frequency and JWT decode from
*Transform Selection…*. Replacing code with a statistics dump is never the intent.

## 6. Defects fixed from 1.0.0

### FIX-1 — YAML reader rewritten

Replaced with an indentation-stack parser. Now handles nested maps, sequences (`key[0]`),
sequences of maps, multi-document files (`---`), block scalars (`|`, `>`) and flow collections
(`[a, b]`, `{k: v}`).

Pinned by `YamlParserTest.dedents correctly when returning to a shallower level`.

**Known limits, stated rather than hidden:** anchors/aliases (`&a` / `*a`), merge keys (`<<`)
and explicit tags are kept as literal text, not expanded.

### FIX-2 — `@ConfigurationProperties` implemented

- On the annotation: keys bound under the prefix, per profile
- On each field of the annotated class: that field's resolved value
- **Relaxed binding** — `maxPoolSize` matches `max-pool-size`, `max_pool_size`, `maxpoolsize`

### FIX-3 — Property lookups cached

`SpringPropertyIndex`, a project-level service, parses all `application*`/`bootstrap*` files
once and reuses them until `VirtualFileManager.getModificationCount()` changes.

### FIX-4 — Inlay group corrected

`TYPES_GROUP` → `VALUES_GROUP`. Also `providerId` → `dev.utility.spring.property.hints`.
